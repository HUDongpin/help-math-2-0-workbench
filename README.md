# HELP Math Flash to JavaScript

This repository is the migration workbench and Next.js application for the
evidence-led recovery of the owner-provided HELP Math Flash library. Read
`AGENTS.md`, then invoke `$flash-to-js` for every FLA/SWF migration.

No animation is considered faithfully migrated merely because it runs in a
browser. A public-library item must pass the strict migration validator,
full-frame/scenario comparison, language and audio review, product QA, human
visual review, and owner acceptance.

The human/owner handoff is defined in
[`docs/PILOT_ACCEPTANCE_RUNBOOK.md`](docs/PILOT_ACCEPTANCE_RUNBOOK.md). Its
signatures must be entered by the named people in each migration manifest;
neither Codex nor a generated review packet may sign for them.

Machine-readable evidence lives in `catalog/`, including the source manifest,
placement catalog, canonical assets, duplicate groups, missing and unreferenced
sources, audio associations, lessons, and batch queues. Exact workstation tool
versions are recorded in `catalog/toolchain.json`.

`catalog/completion-ledger.json` is the fail-closed per-animation strict
admission authority. It is generated by running the strict validator against
every migration and records the validator version/hash plus each admitted
manifest hash. A handwritten `status: complete` is insufficient. The current
ledger has zero admitted entries.

Complete-lesson publication is a separate, stricter gate.
`catalog/lesson-releases.json` declares the exact release membership and source
order, while `catalog/lesson-release-ledger.json` hash-binds that declaration to
the current completion ledger. Grade 4 Lesson 3 is the first atomic release: 39
active XML pages plus one course shell, developed as two parallel 25+15 shards.
It remains wholly unpublished at 0/40 through 39/40 and opens only when all
40 exact source assets have strict completion entries. Current JavaScript output,
Ruffle playback, or a partial strict subset cannot open this lesson gate.

## Preserved sources

The canonical local archive is:

```text
source-assets/flash/HELP MATH_ORIGINAL FILES/
```

The top-level `HELP MATH_ORIGINAL FILES` path is a compatibility symbolic link.
Neither path belongs in ordinary Git or a web deployment. The freeze manifest
is `catalog/source-manifest.sha256`; its own SHA-256 is
`f0a33c8a3d15afd7340e9ea5523385428bae7546bd8d4227a3a8977ab8914318`.

Verify the archive without modifying it:

```bash
npm run verify:sources
```

See `docs/ARCHIVE.md` for the separate private-archive boundary and recovery
procedure.

## Build or run the applications

The product application is the isolated `@helpmath/web` workspace:

```bash
npm run dev
npm run build
```

English is served without a URL prefix and every public route has a Spanish
counterpart under `/es`:

- `/library` — fail-closed public catalog; standalone strict entries appear,
  while declared complete lessons appear only when their atomic release gate is
  open.
- `/courses/3/1` — grade/lesson course sequence.
- `/animations/[animationId]` — unified modern animation player.
- `/migration-status` — source, alias, missing-source, and progress ledger.
- `/reference/[animationId]` — local-development SWF/Ruffle forensic route;
  disabled in production.

The reviewed preview routes are `/demos`, `/demos/conversion-1-2`, and
`/demos/conversion-1-4`; none is represented as a completed fidelity migration.
The application consumes the reviewed completion ledger and dynamic registry
from `catalog/` and `packages/demos/`; see `docs/DEPLOYMENT.md` for the required
monorepo deployment boundary.

Local authentication is a development-only candidate and is not a production
capability. Its exact Clerk fail-closed requirements and the separately gated
future Supabase Auth transition are recorded in
[`docs/AUTH_PROVIDER_TRANSITION.md`](docs/AUTH_PROVIDER_TRANSITION.md).

The earlier two-animation workbench remains available for regression work:

```bash
npm run dev:workbench
npm run build:workbench
```

`Conversion_1_2` and `Conversion_1_4` are runnable conditional-review previews.
They are not strict migrations and are not presented as production-complete.

## Rebuild the intake catalog

The catalog generator streams hashes, parses FWS/CWS headers, pairs FLA/SWF,
tolerantly reads the original course/key-term XML, resolves bilingual audio,
and produces stable placement and canonical IDs:

```bash
npm run catalog:build
```

The command fails when the approved archive totals or the universal 12 FPS
contract do not match. It never writes inside the source archive.

## Scaffold migration work

Create or verify the approved pilot set and import only catalog-backed intake
evidence:

```bash
npm run scaffold:pilots
npm run sync:migrations
npm run audit:pilots
npm run sync:machine-audits
```

The machine audit records FFDec/swfmill headers, tags, scripts, ActionScript
signals, external-call candidates, and source/output hashes. It remains
`partial` and never advances status: FLA authoring inspection, authoritative
runtime traversal, audio timing, and visual baselines are separate gates.

Preview a production batch without writing:

```bash
npm run scaffold:batch -- --batch batch-001 --dry-run
npm run scaffold:batch -- --batch batch-002 --dry-run
```

The G4 L3 MVP uses two explicitly declared development shards: `batch-001`
(25 members) and `batch-002` (15 members). They have no strict-completion
dependency on each other, so their workspaces may be scaffolded in parallel
when the completion ledger is current. This only opens workspace preparation;
it does not authorize implementation or satisfy any fidelity or acceptance
gate. `batch-003` stays closed until the entire 40-member G4 L3 release is
strict-complete, and every later batch requires the immediately preceding
batch. A stale or malformed ledger closes every write-mode gate. `--next`
selects the first catalog batch not yet admitted, and `--dry-run` provides a
write-free preview. For an individual animation:

```bash
npm run scaffold:migration -- <animation-id> --fla <path> --swf <path>
node skills/flash-to-js/scripts/validate_migration.mjs \
  migrations/<animation-id> --allow-draft
```

After the G4 L3 workspaces exist, reproduce the bounded machine-only source
audit and inventory layers with:

```bash
npm run sync:g4-l3-workspace-audits:check
npm run sync:g4-l3-workspace-inventories:check
npm run report:g4:l3:m2-readiness:check
npm run report:g4:l3:runtime-acquisition:check
npm run sync:g4-l3-runtime-acquisition:check
npm run report:g4:l3:m3-readiness:check
npm run report:g4:l3:animate-authoring:check
```

The inventory check covers all 40 release members and verifies 40 machine SWF
definition CSVs, 40 machine audio-candidate CSVs, and 40 hash-bound receipts
under `audit/machine/`. It also verifies that the 80 canonical
`asset-inventory.csv` and `audio-inventory.csv` files retain their prior bytes;
machine candidates never populate those acceptance-facing inventories. The
source audit is likewise artifact-only and intentionally creates zero
`migration.json` bindings. These artifacts record static SWF definitions,
archived embedded-audio payloads, and catalog audio media facts only. They do
not establish authoring structure, runtime reachability, language correctness,
synchronization, listening quality, or acceptance. The final command validates
the exact artifact/receipt bindings and reports static machine-audit
completeness independently from the still-closed authoring, original-runtime,
specification, implementation, and strict-completion gates.

The runtime-acquisition check binds those static facts to a fail-closed,
ordered 40-member evidence contract. It requires natural original-runtime
execution before any supplemental direct seek; separates root and nested frame
domains; inventories EN/ES, interaction, random, audio, navigation, terminal,
and Replay obligations; and keeps every capture/acceptance flag false. It does
not launch Animate, Ruffle, an original runtime, or a browser. Ruffle remains a
forensic reference only, and each bounded capture session still requires a
fresh workstation-capacity preflight plus the named human roles recorded by the
runbook.

The final two commands materialize exactly one machine-owned planning artifact
at `audit/machine/g4-l3-runtime-acquisition-plan.json` in each of the 40
workspaces and validate the resulting artifact set. Every operator field,
runtime context, event/capture schedule, baseline manifest, PNG list, receipt,
and signature remains empty; every artifact is non-runnable. The materializer
prevalidates all 40 workspaces and physical sources before its atomic write,
does not edit `migration.json`, and cannot launch a tool or create acceptance
evidence. The M3 readiness report binds the artifact set and the 40 current
technical-manifest projections while leaving authoring, runtime, baseline,
implementation, review, and publication acceptance gates closed. For FLA-backed
members, the artifact now binds the validated work-only authoring audit without
promoting it to original-runtime evidence or authoring acceptance.

The final authoring command re-hashes the 29 paired FLA/SWF sources, every
declared run receipt, read-only working copy, script, process log, raw Animate
report, native-stage PNG, and work-only evidence document. It currently
records all 29 paired members as hash-valid work-only authoring audits. Failed
attempts remain preserved as fail-closed diagnostics; use the generated result
index summary for the current attempt totals instead of copying a count into
documentation. These results do not establish shipped-SWF runtime behavior,
JavaScript fidelity, audio, RMSE, human review, owner acceptance, strict
completion, or publication.

`--allow-draft` verifies workspace shape and intake evidence only. Omit it only
after the audit, baseline, implementation, full-frame evidence, reviews, and
acceptance checklist are genuinely complete.

## Deterministic capture and validation

Every modern renderer must implement deterministic `?frameDomain=`,
`?requirementId=`, `?trace=`, `?entryStateSha256=`, `?frame=`, `?scenario=`,
`?lang=en|es`, and `?seed=` contracts. The stage reports the matching
`data-animation-id`, frame, domain, requirement, trace, entry-state, scenario,
language, and seed attributes.
`runtime.frameCount` remains the SWF root-frame count; longer nested MovieClips
are validated in separately declared frame domains.

Coverage-v2 acceptance is fail-closed across four linked evidence layers:

1. `audit/frame-domain-disposition.json` enumerates every root-reachable source
   timeline; no `unresolved` disposition may remain.
2. `audit/trace-specs/<requirement>.json` defines either a linear root
   direct-seek proof or a source-evidenced natural interaction schedule. Nested
   domains and all interactive scenarios require the latter.
3. Original-runtime and implementation capture manifests bind the exact
   animation, requirement, domain, trace, entry state, scenario, language,
   seed, native stage, and every PNG hash.
4. Full-frame metrics bind both capture-manifest hashes and each exact baseline
   and implementation frame hash before RMSE thresholds are evaluated.

Direct seek or a documented Rewind-plus-sequential-step sequence can prove only
frame-accurate visuals for a linear root domain. It
cannot prove course-shell navigation, interaction branches, scoring, terminal
behavior, or Replay. Those require natural runtime execution evidence.

```bash
npm run capture:keyframes -- --help
npm run compare:frames -- --help
node skills/flash-to-js/scripts/validate_migration.mjs migrations/<animation-id>
```

Raw full-frame archives belong under the ignored `artifacts/full-frame/` root.
Migration workspaces retain their archive path and digest, all metrics, key
teaching frames, every failed/outlier frame, and diff evidence. Ruffle is a
versioned forensic reference only; it is never the production renderer.
